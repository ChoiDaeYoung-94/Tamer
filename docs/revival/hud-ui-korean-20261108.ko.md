# 플레이어 정보 표기와 오프라인 글꼴 관측

플레이어 정보의 영문 개발용 표기를 골드·닉네임·동료 수·공격력·공격 속도·이동 속도로 바꾼다. 수치 바인딩, 버프 분기와 `LocalPlayerData["NickName"]` 저장 키는 유지한다. 9개 표시 치환을 되돌리면 기준 `83aea8a6e57267f2ff42303ab3b00d13b6ddc2f4`의 소스와 정확히 일치한다.

기존 오프라인 Intro→Login 관측기에 최초 TMP Ellipsis 경고의 UI 객체·글꼴·문자/글리프 연결 상태를 남기는 진단을 추가했다. 원래 경고·예외를 원래 로그 처리기에 그대로 전달하며, 경고를 숨기거나 글꼴 조회 테이블을 초기화하지 않는다. 텍스트 내용·닉네임·계정 값은 기록하지 않는다. 관측기 설치는 별도 앱 ID와 debug Player에 한정되며 운영 Player에는 해당 컴파일 기호가 없다.

현재 검증: 표시 치환의 정확한 역변환, 저장 키와 계산/분기 보존 확인. 변경한 두 구성요소를 고정 Unity 6000.3.25f1 참조 279개로 사전 컴파일했으며 종료 코드 0이다. 기존 직렬화 필드/숨김 멤버 및 사전 컴파일의 중복 형식 경고는 보존했다. 이는 전체 Android Player 컴파일이나 실제 화면 검증을 대신하지 않는다.

실행 결과(`c80cdaa`): 실제 HUD prefab과 원래 표시 메서드로 세 화면비×일반/버프 6개 렌더를 만들었다. 긴 합성 닉네임과 큰 골드 값의 배치/높이 검사는 6개 모두 통과했고 일반 Android 스크립트 68개 어셈블리 컴파일과 운영 IL 7개 검사도 통과했다. 운영 어셈블리에서 시험용 관측기·임시 Editor 진입점 제외를 확인했다.

시각 확인에서 상단 골드가 LiberationSans SDF를 사용해 새 한글 두 글자가 네모로 표시되는 문제를 발견했다. 정보창의 DungGeunMo 표시와 구분하며, 배치 검사 통과를 글리프 표시 완료로 표현하지 않는다. 원래 경고를 유지한 관측에서 TMP_playerNickName/DungGeunMo SDF/공개 Regular·내부 Bold가 6회 일치했다. 이 글꼴의 비어 있는 굵기 대체 표와 관련된 경로를 최소 수정 후보로 좁혔다. 아직 Player에서 원인/수정 완료로 확정하지 않는다.

실행 전체는 실패로 보존한다. Editor/CLI 종료0 뒤 자체 컴파일러 자식 프로세스가 남아 자기 Job을 종료했고, 최종 결과 판독기도 UTF-8 한국어 JSON을 cp949로 읽어 종료1이 되었다. 별도 UTF-8 후속 감사에서 보호7523파일·파일집합/임시 두 설정·Editor 소스쌍의 복구, 자기 Job Dispose와 자식/Editor 부재, 새 공유 ADB 연결 신원을 확인한 뒤 원래 실행 창 안에서 전체 반환했다. 이 후속 감사의 성공으로 원래 실행 실패를 덮지 않는다.

다음: Editor를 통해 원래 HUD prefab의 한글 글꼴 연결·닉네임 굵기를 보완하고 고정 문구를 검토한다. 다음 렌더는 글리프 지원 여부도 검사한다. 별도 새 Editor 프로세스에서 원본 글꼴 바이트로 ARM64 격리 APK를 만들고 실물을 확인한다. 서명 후보32에는 이번 변경이 포함되지 않으며 최종 심사/프로덕션은 별도다.

후속 보완: Unity Editor가 만든 prefab에서 상단 골드·플레이어/동료/포획/확인 문구의 글꼴·재질을 기존 한글 픽셀 글꼴에 맞추고, 닉네임과 제목의 Bold를 정리했다. 데이터/이벤트/좌표/GUID를 유지한 6개 TMP 객체의 표시 속성16개다. 새6렌더는 일반11자/9자리 골드와 허용 최대20자 한글 닉네임/Int32최대 골드2147483647을 세 화면비에서 확인했다. 글리프 지원·높이/잘림 검사6개 통과, 관측 중 Ellipsis 경고0이며 기본/최대값 이미지를 시각 검수했다.

이 실행도 전체 실패로 보존했다. Editor/CLI는 종료0이었지만 자기 컴파일러의 argv0가 절대 경로 대신 `dotnet`이라 엄격 선택기가 거절해 정상 종료 요청은0회였고 자기 Job을 정리했다. 최초 속성 감사도 자동 직렬화의 빈 m_Name 끝 공백3개를 거절해 원본으로 복구했다. 이후 전체 diff를 별도 검토했고, 이3개의 비의미 공백만 원래 형식으로 정규화한 Editor 생성본이 원래16속성 감사와 모든 나머지 속성/FileID 일치를 통과해 반영했다. 원래 실패 판정은 바꾸지 않는다. 실제 전체 반환과 새 공유 연결 신원 확인도 완료했다.

기존 ordinary Android68/IL7은 C#·설정·플러그인 등7127파일이 바이트 동일해 재사용했다. 같은 검사를 기록 목적으로 반복하지 않았다. 새 실물 APK/운영판 확인은 아직 미실행이며 다음 별도 빌드 범위에 남는다.
