## 원인과 수정

기존 `OnTriggerExit`는 플레이어가 사망했으면 바로 반환했고, 포획 대상 참조도 해제하지 않았다. 플레이어와 Canvas는 씬 사이에 유지되지만 사망·비활성화·복귀 초기화에서 해당 참조와 버튼을 함께 정리하지 않아 상태가 남았다. 기존 `Capture()`는 대상의 유효성이나 플레이어 생존 상태를 다시 확인하지 않고 바로 동료로 전환했다.

사망 hook, 플레이어 비활성화·복귀 초기화, UI 초기화에서 대상·trigger·버튼을 함께 해제한다. 풀 반환 시에는 반환되는 몬스터가 현재 선택 대상일 때만 해제한다. 이전 플레이어의 지연된 정리가 현재 플레이어의 버튼을 숨기지 않도록 소유자를 확인한다. 선택한 trigger를 벗어나면 사망 여부와 관계없이 해제하고, 다른 사체와 계속 겹쳐 있다면 `OnTriggerStay`에서 다시 선택할 수 있다.

포획 입력은 생존·HP·정원, 활성 상태인 포획 가능 사체와 trigger, `GameManager.IsGame` 및 씬 전환 상태를 확인한다. 검사를 통과한 대상도 먼저 선택을 소비한 뒤 기존 `AllySetting`과 `AddAllyMonster`를 실행하여 중복 입력을 방지한다. 씬 이름을 직접 검사하는 방식은 아니다. 씬·프리팹·직렬화 연결·GUID와 저장 형식은 변경하지 않았다.

## 적 수명 확인 범위

코드상 활성 적은 현재 `MonsterGenerator` 아래에 배치되고 Game 씬 종료 시 함께 제거된다. 재진입 때는 새 생성기가 적을 생성한다. 수정 전 기기 로그에는 인스턴스 수명 관찰이 없으므로, 이를 수정 전 실측으로 단정하지 않는다.

격리 하네스에 이전 생성기의 생존 여부, 이전 씬에 남은 활성 적, 새 씬에서 정상적으로 재사용된 풀 객체, 현재 적 수와 생성기 밖의 적 수를 읽는 관찰을 추가했다. 이 관찰 코드는 게임 상태를 변경하지 않는다.

## 일반 전투 수정본과 하네스 오판정

생산 코드 수정본 `c5188aed377a97c151be7e8e592e10bdde0520ac`의 APK SHA-256은 `7b1b12159d3c1f74467691223c407f59c13d377feaa7746d159bff4bb222104c`이다. 일반 전투와 원래 Game Over OK를 통한 Main 복귀에서 사망 후 Capture 버튼이 사라진 것을 확인했다. Main에서 이전 생성기 생존 false, 이전 씬 잔류 적 0, 현재 적 0을 관찰했다. Game 재진입에서도 이전 씬 잔류 적과 생성기 밖 적은 0이었다. 새 씬에서 풀 객체가 재사용된 경우는 잔류 적으로 세지 않았다.

사용자 승인에 따라 합성 Gold로 원래 상점에서 Bat를 고용했다. 3마리 고용과 이후 6마리 고용을 별도로 실행했으며 Gold 차감, 동료 목록, 메모리 서버 쓰기와 격리 저장 파일을 확인했다. **상점 고용은 전투 포획 성공 증거가 아니다.** 이 일반 전투 시도에서는 실제 Capture 성공을 확인하지 못했다. 홈/복귀 중 개발 PlayerConnection 소켓 오류가 누적되어 마지막 하네스 오류 수는 15였으며, 게임 C# 예외와 구분한다.

## 승인된 결정적 포획 보조

반복 전투 부담을 줄이기 위해 사용자가 격리 앱 전용 대상 생성·무적·포획 확률 고정을 추가 승인했다. `76c4b8a`의 보조 코드는 `TAMER_GAMEPLAY_HARNESS`에서만 컴파일된다. 정확한 격리 package, Editor 외 실행, 합성 계정 준비 상태, 생성한 메모리 서버 객체 일치를 검사한 뒤 버튼으로 근처 NavMesh에 Bat 하나를 생성한다. 해당 대상의 포획 가능 결과만 고정하며 플레이어 피해를 막는다. 별도 버튼으로 무적을 해제한다.

기존 타격·사망 애니메이션·Capture 버튼·`Capture`·`AllySetting`·`AddAllyMonster`·저장 흐름은 우회하지 않는다. 이 보조 조건의 결과는 원래 확률 및 전투 밸런스 검증과 구분한다.
