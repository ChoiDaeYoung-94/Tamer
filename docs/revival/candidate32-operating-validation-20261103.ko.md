# 후보32의 운영 검증·심사 안내 적용 순서

이 문서는 승인된 [두 ABI 내부 후보](candidate32-abi-tools-20261103.ko.md)의 실행 이후 관측할 내용입니다. 현재 후보32 AAB/Play 전달·운영 게임 검증은 미실행이며, 기존31은 정상 Play 설치 후 LD 첫 실행이 흰 화면입니다. 아래 예상 동작을 실제 성공 기록으로 읽지 않습니다. 키·인증·나이 직접 조작, 신규 결제/환불·운영 데이터 삭제의 기존 승인 경계를 유지합니다.

## 실행을 시작할 조건

1. 계정 주간50% 이전의 실행/복구 여유, 다른 프로젝트의 실제 자원 반환과 새 차례, 최신 build HEAD/clean·Console 번호를 확인합니다.
2. 검토된 ARM64+x86_64 계획·전체 소스맵·원본 키/현재 공개 인증서·실제 사용자 JDK 환경을 결합합니다. 종료한 metadata/바로가기는 사용하지 않습니다.
3. 직접 암호 입력으로 AAB1회 생성 후 원본 복구·소유 프로세스 종료, 정확한 두 ABI/서명/리소스/진단 fixture 제외를 확인합니다.
4. 기존 수동 업로드와 새 내부 제공 별도 승인 뒤 정상 Play 업데이트로 실제 code/installer/UID/서명/전달 ABI를 확인합니다. 기존 운영 앱 삭제나 데이터 초기화로 새 화면을 만들지 않습니다.

| 구간 | 필요한 직접 조작/관측 | 통과로 기록할 근거 | 별도 남는 것 |
| --- | --- | --- | --- |
| 시작 | 정상 Play의 실제 제공 버전 첫 실행 | 흰 화면을 지나 Quad D/진입 화면·반응과 지속 실행 확인 | 시작 실패 원인, 실물 ARM64/16KB |
| 기존 계정 | 사용자가 기존 Google/게임 계정 인증 | 기존 캐릭터/진행과 구매 권한의 연속성 | 단순 로그인 성공만으로 서버 쓰기/복원 완료 아님 |
| 신규 손님 | 기존 저장과 분리된 승인 시험 환경에서 사용자가 `Google 없이 시작` 선택 | 선택 전 생성 없음·선택 후 한 계정의 진입·재실행 연속성 | 실제 신규 운영 계정 생성은 해당 직접 조작 범위 확인 후 진행 |

| 삭제 | 최종 화면/소유 확인/접수와 실제 완료를 구분 | 승인된 대상에서 비동기 공급자 완료·재인증·보관 안내 대조 | 운영 계정 삭제는 현재 문서만으로 실행하지 않음 |

## 연령/광고 경로의 관측 구분

모든 나이 입력과 인증은 사용자가 직접 처리합니다. 기존 계정의 나이/저장 상태를 자동 초기화하지 않습니다. 새 중립 입력창의 빈 값과 나이를 입력하지 않아도 계속할 수 있는 선택을 관측하며, 아래 숫자는 서로 다른 연령 구간을 구분할 시험값입니다.

| 경로 | 화면/상태의 예상 | 실제 광고/SDK 관측에서 구분할 점 |
| --- | --- | --- |
| 미응답 전/미상 | 성인 확정 전 광고 불가 | 표시가 없다는 사실과 SDK 초기화·AD_ID/통신이 없다는 증거를 구분 |
| `응답하지 않음` | 계속 플레이·광고 차단 | No Ads 소유 때문에 막힌 결과와 구분 |
| 12 / 13 / 16 | 각각13세 미만·13–15·16–17 구간, 모두 광고 차단 | 각 구간 별도 확인; 동의나 광고를 보려고 성인을 고르도록 유도하지 않음 |
| 18 이상 | 지역별 개인정보 선택 후 허용될 때만 성인 광고 가능 | No Ads 미보유 확인·동의/재고/연결 실패를 분리. 광고 실패를 게임 진입 차단으로 만들지 않음 |
| No Ads 보유 | 광고 없이 해당 버프 | 성인 광고 재생 검증을 대신하지 않음. 구매 회수/권한 이전으로 시험하지 않음 |

소스의 UI 경로는 설정 톱니 → `Account & privacy` → `연령대 다시 선택` / `광고 개인정보 설정 확인`입니다. 실제 제공물의 표기·입력·뒤로가기/재실행을 대조하기 전에는 App access에 최종 동작으로 확정하지 않습니다. 사용자 계정 식별자·토큰·영수증 원문·암호를 공개 증거에 넣지 않습니다.

## 공식 안내를 저장하기 전

Google은 심사용 접근 정보가 재사용 가능하고 지역에 관계없이 유효하며, 외부 Google 로그인과 유료 기능 접근에도 구체적인 영문 안내가 있어야 한다고 설명합니다. 기존 전용 심사 계정의 실제 반복 로그인·유료 접근과 No Ads 여부를 확인한 뒤 [영문 준비안](guest-review-instructions-draft-20261102.ko.md)을 적용합니다. 계정 암호는 Console의 전용 입력란에서 관리하며 공개 문서에 복제하지 않습니다. [공식 심사 로그인 안내](https://support.google.com/googleplay/android-developer/answer/15748846?hl=en)

손님 선택도 서버 저장용 계정을 만들므로 ‘로그인 없음/개인정보 수집 없음’으로 바꾸지 않습니다. 무작위 사용자 ID·인증/서버 저장 목적과 공급자 처리를 기존 `OAuth + 기타`·수집10/공유6 답안과 대조합니다. Google의 Data safety 안내는 기기 밖 전송과 제3자 SDK 처리를 포함해 실제 처리에 맞게 신고하도록 설명합니다. 소스 flag나 무광고 결과만으로 유형을 줄이지 않습니다. [공식 Data safety 안내](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

실제 App access/공개 정책·신고 저장과 최종 정책 심사 전송·프로덕션은 구분합니다. 거절26의 모든 활성 출시 `Not included`도 내부31/32 제공과 별도입니다. [전체 잔여](remaining-recovery-work.ko.md)
