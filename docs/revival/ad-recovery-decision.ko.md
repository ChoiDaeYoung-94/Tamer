# 광고 복구 제품 결정안

2026-09-14, main `188e98d` 기준. 실제 기기·AdMob 읽기 근거는 [9월 14일 광고 검증](families-ad-followup-20260914.ko.md), 포획·전투 근거는 [게임플레이 검증](gameplay-capture-lifecycle.ko.md)을 따른다. 이번 문서는 결정안이며 코드·운영 설정·메시지·스토어 게시를 변경하지 않았다.

## 권장 결정

**A: 광고 차단을 유지한 복구를 먼저 진행하고, 신규 No Ads 판매는 일시 중단하는 안을 권장한다.** 기존 No Ads 권한·복원·무광고 보상은 보존한다. 일반 사용자에게 광고 대신 무료 보상을 새로 주는 밸런스 변경은 포함하지 않는다. 광고 수익 재개는 아래 근거를 갖춘 별도 변경으로 진행한다.

이는 광고에 한정한 우선순위다. 다른 계정·데이터·스토어 제출 조건이 모두 충족됐다거나 지금 출시 가능하다는 뜻은 아니다. 신규 No Ads 판매 중단도 **아직 구현·적용하지 않은 제안**이다.

최종 AAB를 확인하기 전 sample/control APK에 남아 있던 provider·권한을 운영 AAB의 확정값으로 옮기지 않는다. 인터넷 권한은 로그인·저장 등 다른 기능에도 쓰이므로 광고 차단을 위해 앱 전체 네트워크 권한을 무조건 제거하지 않는다. GMA/UMP 완전 제거는 별도의 구현 대안이며 현재 차단 완료와 혼동하지 않는다.

## 사용자가 결정할 항목

1. **복구 순서:** A(광고 차단 유지, 권장) 또는 B(수익 재개 조건을 충족한 뒤 복구).
2. **신규 No Ads 판매 범위:** 전체 신규 판매 일시 중단(권장), 새 복구 앱의 구매 진입만 중단, 또는 기존 판매 유지. 전체 중단과 앱 진입만 차단의 차이는 아래에 명시한다. 어느 안도 기존 주문 처리·권한·복원을 끄거나 SKU를 삭제하지 않는다. 유지하려면 무광고 상태에서도 제공하는 실제 혜택을 상품 안내와 일치시켜야 한다. 현재 무광고 버프·회복 혜택을 다른 상품으로 재설계하는 선택은 이번 안에 포함하지 않는다.
3. **B를 선택할 때만, 광고 이용자 범위:** 모든 이용자를 보수적으로 아동 취급할지, 중립적 연령 확인 후 아동/연령 미상과 그 외 이용자를 구분할지 결정한다. 기존 Play 대상 연령을 정책 회피 목적으로 바꾸지 않는다. 전자는 연령 정보 추가 수집을 피할 수 있으나 광고 수익·이용 경험에 영향이 있고, 후자는 연령 UI·지역별 동의·데이터 처리 검증이 추가된다. 지역별 동의 적용 가능성은 별도로 검토하며 어느 선택도 UMP 검증을 자동 면제하지 않는다.

한 번에 전달할 수 있는 권장 답변은 **“A로 진행하고, 신규 No Ads 판매 전체를 일시 중단하는 안을 준비하세요. 기존 구매 권한과 보상은 유지하세요.”**다. B를 원하면 **“B로 진행하고, 신규 판매는 [유지/전체 중단/새 앱 진입만 중단], 이용자 처리는 [전체 아동 취급/중립적 연령 확인]으로 준비하세요.”**처럼 선택하면 된다. 이 선택은 구현·검증안 준비의 기준이며, 계정 설정 저장·정책 게시·스토어 제출의 구체적인 최종 변경은 별도로 제시한다.

## 신규 No Ads 판매의 정확한 범위

현재 실제 구매 진입은 `Assets/Scripts/Creatures/ShopMan.cs`의 `IAP("ProductNoAds")` → `Assets/Scripts/Managers/IAPManager.cs`의 `BuyProductID`다. 광고 요청 차단과 독립적이며 상품/스토어/세션이 준비되면 구매를 진행하는 코드가 남아 있다. `Assets/Resources/IAPProductCatalog.json`의 로컬 설명은 ‘광고를 제거합니다.’다. 이는 로컬 catalog 관찰이며 현재 Play 상품 안내를 이번 문서 작업에서 다시 읽은 결과가 아니다.

현재 권한 보유자가 받는 추가 효익은 `GoogleAdMobManager.ShowRewardedAd`가 광고 정책 차단보다 먼저 `HasNoAds`를 처리하여 기존 보상을 주는 것이다. `BuffingMan`은 기존 10분 버프를, `PopupManager.Heal`은 HP 회복을 광고 없이 제공한다. 판매를 유지한다면 일반 이용자도 광고가 없는 기간이라는 사실과 구매자에게 실제로 제공하는 이 효익이 구매 직전 안내·Play 설명과 일치해야 한다. 단순히 광고 제거만으로 표현해 새 광고가 존재하는 것처럼 보이게 하지 않는다.

| 판매 선택 | 구체 변경안과 영향 |
|---|---|
| 전체 신규 판매 일시 중단(권장) | 새 앱 구매 UI와 `BuyProductID`의 신규 구매 시작을 막는 변경을 준비한다. 별도로 Play Console의 해당 일회성 상품/구매 옵션 비활성 상태 변경안을 준비해야 구버전·스토어 측 신규 구매 제공에도 대응할 수 있다. 배포 전에 실제 상품 모델과 옵션 범위를 읽고 구체 변경 화면을 제시한다. 기존 영수증 검증·미완료 주문 처리·복원은 유지하며 상태 변경 전후 별도 확인한다. 아직 적용하지 않음 |
| 새 복구 앱의 구매 진입만 중단 | 해당 새 버전 UI/신규 구매 시작만 차단한다. Store 상품은 활성 유지되므로 기존 배포 버전이나 다른 Store 진입에서 구매가 계속 가능할 수 있다. 따라서 ‘신규 판매 전체 중단’으로 표시하지 않는다 |
| 판매 유지 | 구매 경로와 상품 활성 상태를 유지한다. 제공하는 무광고 버프·회복과 현재 일반 사용자도 광고가 없는 상태를 구매 안내에 정확히 반영하는 변경안을 준비한다. 가격·기존 SKU·이미 획득한 권한은 변경하지 않는다 |

[Google 일회성 상품 안내](https://support.google.com/googleplay/android-developer/answer/16430488?hl=en)는 비활성 구매 옵션이 PBL에 반환되지 않는다고 설명하며, 이전 모델에서 이행된 옵션은 별도 호환 상태가 있을 수 있다고도 명시한다. 따라서 이름만 보고 모든 판매 경로가 닫혔다고 판단하지 않는다. [기존 인앱 상품 안내](https://support.google.com/googleplay/android-developer/answer/1153481?hl=en)는 Store 내 직접 구매 진입 가능성도 설명한다. 상품 비활성은 기존 구매자의 권한 삭제·환불·SKU 삭제와 다른 작업이며, 실제 복원 영향은 해당 앱의 검증으로 확인한다.

## B 선택 후 필요한 기술·운영 근거 — 추가 제품 질문이 아닌 수행 항목

- **연령/UMP:** 승인된 이용자 범위에 따라 시작 시 consent 갱신, 필요한 폼, 접근 가능한 privacy options, 오류/취소 시 광고 차단을 연결한다. 현재 sample은 첫 명시적 요청까지 갱신을 지연하고 TFUA=true로 동의 요청을 억제한다. 성인/EEA 운영 흐름으로 사용할 수 있다는 근거가 아니다. [UMP 안내](https://developers.google.com/admob/unity/privacy/gdpr)
- **현재 메시지 설정:** AdMob에서 게시된 유럽 규정 메시지는 확인하지 못했지만 ‘메시지 노출 범위 극대화’는 켜져 있다. 대체 메시지 시도 가능성과 실제 노출을 구분한다. 사용할 앱·지역·파트너·개인정보 URL과 대체 메시지 영향을 구체적으로 제시한 뒤 게시/설정 변경안을 검토한다.
- **공급원:** 현재 목록에는 AdMob(기본)만 있다. 최종 앱에 포함된 SDK·adapter/custom event와 실제 응답 공급원을 대조한다. 아동/연령 미상 요청에는 초기화/로드 전에 아동 처리와 최대 등급 등 승인된 설정을 적용하고, 필요한 인증 버전을 확인한다. [AdMob Families 안내](https://support.google.com/admob/answer/6223431?hl=en)
- **고참여 설정과 5초:** 현재 고참여 광고는 켜짐이다. 끄는 변경은 표준 광고 단위의 시청/종료 단계와 수익에 영향을 줄 수 있지만, 공식 표는 꺼짐 상태도 보상형 reward skip time 최대30초로 설명한다. **이를 끄는 것만으로 5초 종료가 보장되지 않는다.** 보상 취득 시각과 조기 종료 가능 시각을 각각 검증한다. 기존 sample 영상의4.980722–5.029033초 불확실성은 유지한다. [설정 표](https://support.google.com/admob/answer/15525707?hl=en), [Families 형식 요건](https://support.google.com/googleplay/android-developer/answer/9893335?hl=en)
- **실제 소재 문제:** 앱 타이머에서 광고 객체 `Destroy()`를 호출하는 방식을 native 종료 보장으로 사용하지 않는다. 원인이 된 배치/번들/공급원/소재와 첫 표시·X·터치 근거를 연결한다. 공급자가 종료를 보장하지 못하면 해당 경로를 다시 차단하거나 다른 방식으로 변경해야 한다. 지원 문의가 필요하면 비공개 근거 범위를 정해 사용자에게 최종 전송안을 제시한다.
- **배포/Console:** 최종 release AAB를 기준으로 debug/test define·sample ID 누출 여부, 요청 경로, 권한/provider 및 개인정보 선언을 확인한다. 실제 제공 버전과 위반 연결 버전 교체 범위, 대상 연령·광고 포함·Data safety·개인정보 안내 변경안을 대조한다. 내부 테스트 제공과 프로덕션 정책 해소를 구분한다. 수익 설정·게시·제출은 승인된 구체 변경만 수행한다.

이 문서는 출시 허용이나 법적 적합성을 단정하지 않는다. 최신 기기 성공 근거는 보상 후 Home 복귀·원래 X 종료·보상/완료1회 및 control managed 차단이며, 운영 광고의5초 종료·성인/EEA 동의 UI·대체 메시지 실제 노출·native 실패 callback은 아직 미검증이다.
