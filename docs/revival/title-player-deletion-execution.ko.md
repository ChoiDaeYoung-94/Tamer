# 기존 Tamer 타이틀 플레이어 삭제 실행 기록

## 범위와 실행

2026-09-11 사용자가 승인한 기존 Tamer 타이틀의 기존 플레이어 계정 삭제를 PlayFab Game Manager에서 실행했다. 삭제 전 All Players와 전체 기간 검색에서 확인한 고유 대상은 76개다. 각 프로필의 **타이틀 플레이어 삭제**를 선택하고 마스터 계정을 삭제하지 않는다는 확인창을 확인했다. 76개 모두 삭제 확인 후 플레이어 목록으로 복귀했다. 관찰된 제출 실패는 0건이다. 이는 UI 제출 처리의 증거이며 백엔드 소거 완료 영수증은 아니다.

사용자 승인에는 해당 계정의 저장 데이터와 No Ads 데이터 소실이 포함됐다. 신규 테스트 타이틀, 마스터 계정, 타이틀 자체, 카탈로그와 설정은 변경하지 않았다. 기존 대상의 삭제 요청을 반복하지 않았다.

## 시각별 관찰

모든 시각은 2026-09-11 UTC다. 목록, 검색, 세그먼트는 별도 조회이며 동일한 시점의 원자적 집계가 아니다.

**최종 백엔드 삭제 완료는 미확정이다.** 검색 결과의 0명만으로 일반 목록 또는 세그먼트의 잔여 표시를 해소했다고 판단하지 않는다. 비동기 삭제·검색 인덱스·집계 반영 차이일 수 있으나 원인은 확인하지 않았다. 세그먼트의 11명을 삭제 누락 또는 신규 계정으로 단정하지 않으며, 이를 근거로 추가 삭제를 실행하지 않았다.

## 삭제 범위의 한계와 근거 보관

[PlayFab Admin DeletePlayer 문서](https://learn.microsoft.com/en-us/rest/api/playfab/admin/account-management/delete-player?view=playfab-rest)에 따르면 타이틀 플레이어 삭제는 비동기로 처리되며 마스터·퍼블리셔 계정 및 PlayStream 이벤트 이력은 이 작업으로 삭제되지 않는다. 기존 클라이언트가 나중에 계정을 다시 생성할 가능성도 별개다. 계정 생성 설정은 변경하지 않았다.

대상 ID와 개별 제출 시각은 Git에서 제외된 로컬 비공개 감사 JSON에만 보관했다. 이 문서에는 개인 식별자·원시 계정 데이터·인증 값이 없다. 검증은 Game Manager의 실제 UI 관찰과 고유 제출 수 대조로 수행했다. 코드·Unity·Android 빌드를 변경하지 않은 운영 기록이므로 Editor 테스트나 APK 검증은 실행하지 않았다.
