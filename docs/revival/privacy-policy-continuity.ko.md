## 기존 원문으로 이미 확인되는 사실

운영자 표기는 **AeDeong**, 앱 이름은 **Monster Tamer**, 시행일은 **2024년 9월 30일**이다. 일반 개인정보 문의 주소는 [원문의 6절](../../README.md#6-문의)을 그대로 사용한다. 이 기재 사항을 다시 정할 필요는 없다. 추가 개인 연락처를 수집하거나 공개하지 않는다. 일반 문의 주소가 있다는 사실은 삭제 접수·본인 확인·처리가 운영된다는 증거가 아니다.

원문은 개인 식별 정보·사용 데이터·기기 정보의 수집 가능성, 서비스/지원/개선/법적 의무 목적, 법적 요구 또는 서비스 제공 제3자 공유, 일반 보안 안내와 정책 변경 안내를 담는다. **보관 기간·기산점·예외, 계정 삭제 방법/범위/기한, 재가입·No Ads 복원은 명시하지 않는다.** 기간이나 처리 약속을 새로 넣지 않았다.

## D1–D8에서 남는 범위

아래 표는 정책 원문 확인 당시의 범위다. 이후 별도 승인한 기존 76개 타이틀 계정 정리는
[최종 일반 목록·세그먼트 0명](title-player-deletion-execution.ko.md)으로 확인됐다.
그 계정들에 대한 Public→Private 이행은 남은 작업이 아니며 실제 대상 재등장 시에만 재평가한다.
이는 향후 운영 삭제 접수·보관·재가입 정책의 확정을 뜻하지 않는다. 현재 결정 상태는
[실행 준비 문서](privacy-execution-readiness.ko.md)를 따른다.

| 항목 | 이미 확인된 부분과 남는 부분 |
| --- | --- |
| D1 | 운영자·일반 문의·기존 정책 URL·기존 시행일은 확인 완료. 남는 것은 실제 삭제 접수 경로와 처리 책임·실행 방식이다. 새 정책 개정일은 개정할 때 정한다. |
| D2–D4 | title/master 삭제 영향, 대상별 보관/예외, 재가입·구매 복원은 원문에 없어 미정이다. 기존 진행도/No Ads를 임의 폐기하지 않는다. |

## 실제 처리와의 대조 경계

[기존 기술 감사](privacy-data-safety-audit.ko.md)와 [Data safety 초안](data-safety-draft.ko.md)은 각자의 조사 소스를 유지한다. 앱의 계정 ID·닉네임·진행도·구매 권한 처리에 비해 기존 원문은 구체적인 수신 SDK와 보관/삭제 설명이 부족하다. 반대로 원문의 이름·이메일 예시만으로 실명이나 실제 이메일 수집을 확정하지 않는다. 합성 로그인 문자열과 캐릭터 구분값을 사용자 이메일·성별로 분류하지 않는다. 광고 managed 호출 차단을 SDK 전체 수집 없음으로 확대하지 않는다. 과거 감사의 UMP 미호출 관측은 PR128 이후 현재 코드의 결론으로 재사용하지 않는다.

2026-09-11 확인한 [Google Play User Data 공식 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)은 접근 가능한 정책 URL과 앱 내 정책, 실제 처리·수신자·보관/삭제 설명 및 Data safety 정합성을 요구한다. [계정 삭제 공식 안내](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)는 해당 계정 생성 앱의 앱 안팎 삭제 요청 경로를 다룬다. 기존 URL과 본문이 보존됐다는 확인은 이 모든 요건 충족이나 심사 통과 판정이 아니다.

문서 대조 작업이므로 Unity·Android·서버 테스트를 반복하지 않았다. 정책 본문 변경, 운영 계정/데이터 처리, 배포·스토어 설정 변경도 없다.
