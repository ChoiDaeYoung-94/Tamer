## 남은 실제 연결 작업

1. 승인된 호스트·영속 DB·HTTPS origin·고정 title·비밀 주입·최소 API 권한을 정한다. 현재 SQLite 단일 호스트 구현과 Azure Functions/Table 설계안을 혼동하지 않는다. 요청 본문 로깅 방지, 접근 제한, 백업·복구 설정을 포함한다. 이 초안은 자원 생성이나 배포를 승인·실행하지 않는다.
2. 앱 시작에서 `DeletionPresenter.ConfigureSessionService`와 같은 origin/title의 복구 bootstrap을 연결한다. 현재 세션 확인 지원은 단일 custom ID 또는 AndroidDevice 익명 계정으로 제한된다. 실제 출시 지원 계정 유형과 맞추고, native PGS 등 미지원 유형은 필요한 별도 소유 확인 흐름을 구현한다.
3. 앱 밖에서도 실제 요청·소유 확인이 가능한 페이지를 제공한다. 미제공 안내나 합성 데모를 삭제 요청 URL로 등록하지 않는다. 앱 내 정책 링크도 연결 상태를 확인한다. 현재 `Assets/Scripts` 검색에서 공개 정책 URL 열기 경로는 확인하지 못했다.
4. 위 보관 표를 확정한 범위에 한해 백업·구매 증거·요청 대장 정리를 구현한다. 알 수 없는 소유자의 파일을 일괄 삭제하거나 기존 구매 권한을 새 계정에 자동 부여하지 않는다.
5. 환경이 연결된 뒤 승인된 비운영 계정으로 실제 인증·접수·응답 유실·재시작 복구를 검증한다. 기존 합성 테스트를 반복해 운영 연결 증거로 삼지 않는다. 운영 계정 삭제는 수행하지 않는다.
6. 실제 제공 버전, 광고 설정 및 위 확정 사실에 맞춰 본문·Data safety·앱/웹 안내를 함께 검토한다. 기존 정책 URL을 유지하고 새 시행일은 게시 결정 시 정한다. 최종 완료 worker·강제적인 추가 인증 수단·새 지원 창구를 일률적으로 요구하는 범위로 확대하지 않는다.

문서 변경만 수행했다. 소스 경로와 기존 정책 본문을 읽기 대조하고 diff를 확인했다. Unity `6000.0.81f1`, CLI `1.0.0-beta.8`, Android min24/target36 기준은 변경하지 않았다. Editor·기기·테스트·APK 빌드를 다시 실행하지 않았으며 새 APK SHA-256은 없다. 운영 endpoint, 실제 삭제, 공급자 잔존 자료의 파기, SDK 네트워크 전송·보관, 현재 Play Console 값과 공개 게시 결과는 미검증이다. 이전 검증은 각 연결 문서의 실제 커밋·결과 범위를 따른다.
