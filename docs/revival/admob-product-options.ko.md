허용이 아니다. 기존 Play 대상 연령 기록은 9~12·13~15·16~17세이며 이번에는
Play Console 선언을 재조회하거나 변경하지 않았다.

2026-09-28 기존 Chrome 세션에서 AdMob 앱 설정과 보상형 광고 단위의 설정 화면을
제한적으로 읽었다. 확인한 화면에서는 실제 소재의 5초 내 닫기를 보장하는 근거를
확보하지 못했다. 이는 확인한 화면 범위의 관측이며 숨은 기능의 부재를 증명하지 않는다.
편집 화면은 값 변경·저장 없이 취소/닫기로 끝냈다. 계정 식별자와 원시 화면은
이 문서에 넣지 않는다. 동의 메시지·공급원 전체를 이번에 재감사한 것으로 표현하지 않는다.

[Families 정책](https://support.google.com/googleplay/android-developer/answer/9893335?hl=en)은
아동 또는 연령 미확인 사용자에게 제공하는 **앱 사용이나 게임플레이를 방해하는**
광고·수익화가 5초 후 닫히지 않는 것을 금지한다. 보상형·명시 동의형 광고도 포함된다.
모든 보상형을 연령·배치와 무관하게 금지한다는 규칙은 아니다. 현재 버프·HP 회복은
게임 화면을 가리는 네이티브 전면 보상형이므로 이 조건을 적용해야 한다고 판단한다.
사용자가 시청을 선택했다는 사실만으로 해당 조건에서 제외되지 않는다.

모든 미성년에게 동일한 Families 5초 규칙이 적용된다고 단정하지 않는다.
현재 전체 미성년 차단은 연령·지역별 보호와 닫기 근거가 미완성인 상태의 보수적
코드 경계다. 성인에게 Families 5초 조건을 그대로 일반화하지 않지만,
[보상형 정책](https://support.google.com/admob/answer/7313578?hl=en)은 명시적 선택,
약속한 보상, 건너뛰기·거절 후 정상 이용 보존을 요구한다. 성인 자기신고만으로
기존 대상 연령과 지역·동의 검토를 통과한 것으로 처리하지 않는다.

[AdMob 보상형 설명](https://support.google.com/admob/answer/7372450?hl=en)은
소재에 따른 보상 카운트다운을 5~30초로 설명한다.
[고참여 설정 표](https://support.google.com/admob/answer/15525707?hl=en)는 보상형의
보상 건너뛰기 시간을 꺼짐에서 최대 30초, 켜짐에서 최대 60초로 안내한다.
이는 보상 취득 시점과 조기 종료 시점의 구분이 필요한 자료이며, 고참여 OFF만으로
모든 실제 소재에서 5초 내 닫기를 보장하는 근거가 아니다. 기존 공식 샘플 한 회의
첫 광고 픽셀→실제 X 약 8초 관측은 유지한다. 모든 운영 소재가 8초라는 뜻도,
다른 샘플이 짧게 나오면 전체 운영 경로가 적합하다는 뜻도 아니다.

| 출시 영향 | AdMob-only 조건에서 아동/연령 미확인의 현 보상형 5초 종료 보장 경로를 확보하지 못했으므로 해결까지 출시 보류 | 승인 후 새 배치·게임 보상·동의·상품 안내·기기 검증 필요. 설계 선택만으로 운영 활성화나 출시 허용이 아님 |

B의 배너는 **보상 조건이 될 수 없다**. 광고 노출·클릭·시청 시간·닫기 여부를
Gold 교환이나 버프·회복 지급에 연결하지 않는다.
[비보상 인벤토리 정책](https://support.google.com/admob/answer/48182?hl=en)은
비보상 광고 시청에 대한 보상을 금지한다. 일반 interstitial이나 native 광고를
기존 보상형 버튼에 연결해 이 제한을 우회하지 않는다. 광고를 제공할 수 없는
지역·동의 상태에서도 승인된 게임 내 교환 조건은 같아야 한다.

## 추천과 작업 범위

현재 제약 안에서 **실제 구현 경로를 확보하기 위한 추천은 B의 설계 변경 승인**이다.
A의 계약 유지가 우선이라면 그 결정을 존중하되 현재 상태를 복구 완료로 보고할 수 없다.
B는 기존 비구매자의 광고 완료 보상을 게임 경제로 옮기는 변경이므로 9월 21일의
확정 계약에서 자동 승인된 것으로 해석하지 않는다. 기존 No Ads 상품을 없애거나
신규 판매를 멈추는 선택을 다시 묻지 않는다. 대상 연령 변경·Unity Ads 재도입·
지원 문의도 두 안에 포함하지 않는다.

B 승인 후 구현은 다음 범위로 나눈다.

1. `ShowRewardedAd`의 기존 No Ads 우선 경로와 세션 안전 처리를 보존한다.
   `AdEntitlement`의 동일 권한 판정을 일반 광고에도 사용한다. 초기화 전에
   구매 권한이 확정되지 않으면 새 광고를 요청하지 않으며, 권한 획득·복원 시
   캐시/표시 광고를 폐기한다. 영수증·상품 조회 실패로 기존 권한을 회수하지 않는다.
2. Main 메뉴 배너의 생성·표시·숨김·파괴를 화면 수명과 연결한다. 전투 진입,
   팝업/개인정보 옵션 진입, 동의 변경, No Ads 획득과 관리자 종료에서 정리한다.
   자동 갱신도 초기 요청과 같은 보호 조건을 적용한다. 광고 미노출은 정상 이용을 막지 않는다.
3. 일반 광고용 권한 판정을 전면 보상형 필터와 분리한다. unknown을 성인 취급하지
   않으며 SDK 초기화/로드 전 연령 보호·G 등급·동의 조건을 적용한다.
   지역 검토와 운영 광고 차단을 그 과정에서 임의 해제하지 않는다.
   [AdMob 초기화 안내](https://developers.google.com/admob/unity/quick-start)는
   초기화 시 사전 로드 가능성을 설명하므로 신호 적용 순서를 보존한다.
4. 게임 내 교환은 별도 기능으로 구성한다. Gold 차감·지급의 원자성, 중복 클릭,
   씬/계정 전환, 저장 실패를 다룬다. 현 버프의 10분 지속 및 저장 키를 보존한다.
   No Ads 이용자는 같은 버튼에서 기존 즉시 혜택을 받고 Gold를 차감하지 않는다.
   가격·회복량·쿨다운 값과 상품 문구는 승인된 설계에 맞춰 확정한다.
5. 광고 단위 생성·게시·수익 설정 등 브라우저 쓰기는 통합 담당과 조율한다.
   먼저 가짜 광고/게임 데이터와 공식 테스트 단위로 검증 가능한 구현을 준비한다.
   새 공급원·SDK 설치나 운영 광고 호출을 이번 문서 승인으로 추론하지 않는다.

## 검증 완료와 결정 대기

이번에 완료한 것은 현재 코드 경계 확인, 공식 자료 검토, 기존 AdMob 설정의 제한된
읽기 감사와 두 설계의 범위 정리다. 문서만 변경했으므로 Unity/Python 테스트나
APK 빌드를 실행하지 않았다. 변경 없는 8초 테스트를 반복하지 않았고 폰/Editor는
Data 작업에 양보했다. 따라서 새 APK SHA-256 및 런타임 성공 결과는 없다.
기준 도구는 Unity `6000.0.81f1`, CLI `1.0.0-beta.8`, Android min24/target36·ARM64이며
`tools/revival/toolchain.json`과 `Packages/packages-lock.json`을 변경하지 않았다.

결정 대기는 **A의 보상 계약 유지 vs B의 분리 설계 승인**이다. B를 선택한 경우에도
Gold 교환의 비용·회복량·쿨다운은 아직 제안값이 확정되지 않았으며 승인 전 지급 규칙을
코드에 넣지 않는다. 이 문서는 미성년 무료 즉시 보상이나 No Ads만 보상 접근이 가능한
제품을 승인하지 않는다.

후속 구현 검증은 실제 변경에 관련된 최소 범위로 실시한다. B에서는 가짜 광고를
사용한 차단·No Ads·동의 변경·화면 수명 검사와 합성 게임 교환·저장 검사를 먼저 수행한다.
그 다음 격리 빌드에서 실제 예약 영역/오클릭/회전·해상도/백그라운드 복귀와
초기화 전 신호·native 자동 통신·No Ads의 요청/표시 0을 확인한다.
동의 실패·연령 미확인 처리, 대상 SDK 인증과 최종 manifest/AAB·데이터 공개 항목도
대조한다. A에서는 공급 형식·설정 등 새로운 근거가 생긴 경우에만 실제 종료 시각과
보상 시각을 별도로 검증한다. 과거 결과나 한 번의 짧은 샘플로 운영 경로를 승인하지 않는다.

통합 담당에게 전달할 마지막 질문의 초안:
“기존처럼 광고를 완료해 버프·회복을 받는 방식을 유지하고 해결까지 출시를 보류할까요,
아니면 일반 광고와 보상을 분리하는 설계로 변경할까요? 추천은 후자입니다.
후자는 비구매자의 버프·회복을 게임 내 Gold 교환 등으로 설계하는 작업이 추가되며,
기존 No Ads의 무광고·즉시 버프/회복·구매/복원 혜택은 유지합니다.
교환 비용과 반복 제한을 포함한 구체 밸런스안은 구현 전에 검토 대상으로 남깁니다.”
