## Play 생성 APK의 정적 검사

같은 Console 아티팩트에서 Google Play 서명 범용 APK를 내려받아 원본과 비공개 검사 사본을 보존했습니다. 76,553,406B / SHA-256 `9a6f04e83b9d8b4087c787094149eee7a810092c83cd70e846d1d5a21dfc989b`입니다. 현재 앱의 Play 앱 서명 인증서와 일치하며 업로드 인증서와는 별개입니다.

서명·code31/1.0.5·min25/target36·ARM64·nondebug/nontest와 승인한 AAB의 리소스 payload 일치를 확인했습니다. native6개의 ELF LOAD/보수적 RELRO 배치는 통과하고 strict 끝주소 modulo 진단3개는 남습니다. 실제 aapt manifest의 `extractNativeLibs=true`와 native6개 압축 저장을 구분했습니다. 이 APK의 원시 native ZIP 엔트리가16KB 경계에 맞는다고 주장하지 않으며, 설치 시 추출되는 구성의 기본 정적 검사 통과입니다.

초기 비공개 보고서의 boolean parser가 aapt의 전체 namespace와 텍스트 `true` 표현을 인식하지 못해 explicit 값을 null로 기록했습니다. 보존한 manifest 원문으로 true를 확인한 보충 기록을 추가했으며, 원래 보고서를 덮어쓰지 않았습니다. 압축 라이브러리와 ‘명시적 추출 금지’의 충돌 없음이라는 결론은 그대로입니다. 모든 split APK·실제16KB·설치/시작 성공으로 확대하지 않습니다.

## 네이티브 기호 첨부

기존 빌드 산출물에서 libmain/libunity/libil2cpp3개의 Build ID를 실제 AAB31/Play APK31과 대조하고 symbol table이 있는 파일만 묶었습니다. 36,859,682B / SHA-256 `98c05100d0bfa5bcdbc7259ee7553fdb21505d346ff0c2d2e2f50b53eac28554`이며 나머지 native3개까지의 전체 기호 제공은 아닙니다. 새 빌드·제품 수정 없이 사용자가 ‘네이티브 디버그 기호’ 행에 수동 업로드했습니다.
