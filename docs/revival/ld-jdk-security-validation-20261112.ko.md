# 별도 JDK의 실제 LD 빌드·보존 업데이트 — 2026-11-12

게임 source `1d09455af10ea17e2b6dd469b7cae53978d5df51`에서 공식 배포 해시로 확인한 **Temurin17.0.21+9를 실제 Gradle에 사용**해 별도 오프라인 x86_64 검토 APK를 한 번 생성했습니다. Unity는 현재 검증 기준인6000.3.25f1이며, 이 결과는6000.3.27f2 Editor의 보안 패치 적용을 뜻하지 않습니다.

## 확인한 범위

- 새 JDK의 기본 신뢰 관리자에서 해당 eMudhra 관련 G3/AAA 인증서가 없음을 확인했습니다. 기존/새 JDK 인증서 저장소·OS 신뢰 저장소는 수정하지 않았습니다. 이는 모든 코드 서명 정책이나 Unity Editor 자체의 보안 검증과 다릅니다.
- 빌드 자식 Java 실행 경로와 Editor의 Gradle 실행 명령이 모두 별도 JDK를 가리켰습니다. 임시 선택 뒤 기존 JDK 설정 두 항목을 존재 여부까지 원복했고 원본·기존 키·공유 ADB 신원과 소유 자식 종료를 대조했습니다. SDK 전체 실제 반환은19:28:20KST입니다.
- APK의 별도 앱 ID/debug 서명·x86_64/min25/target36·네트워크/운영 광고·결제 권한 및 provider 제외·백업18항목을 확인했습니다. 실제 SDK·서버 동작이 차단된 시험 앱입니다.
- LD Tamer의 기존 시험 앱을 삭제/초기화 없이 업데이트했습니다. 앱 UID·안정 설정9개·사용자가 앞서 직접 선택한 연령 응답 거절·합성 저장 공간을 보존하고 마을 진입 원화면을 확인했습니다. 세션용4키의 변경과 횟수+1은 안정 설정과 구분했습니다.
- 마을 사냥터 표지는 `사냥터 / 눌러서 입장`으로 통일했습니다. 시작 위치에서 표지가 보이지 않아 해당 글자의 별도 화면 판독은 하지 않았습니다. 기존 사망 안내 관련45검사와 ARM64 동선 근거를 재사용했고 LD 전투/사망을 반복하지 않았습니다.
- 오프라인 개발 PlayerConnection의 알려진 socket 진단3줄은 원시 로그에 보존했습니다. 마을 화면의 앱 진단0과 원시 로그 전체 오류0은 같은 주장이 아닙니다. 관측 JSON의 기존 경로 읽기1회 실패도 앱 실패로 바꾸지 않았습니다.
- 자체 시험 앱과 LD를 정상 종료하고19:41:04KST 실제 반환했습니다. 다른 인스턴스와 운영 앱/계정/저장/No Ads는 건드리지 않았습니다.
