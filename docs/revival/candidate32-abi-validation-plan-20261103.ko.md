# 다음 내부 후보의 ARM64+x86_64 검증안 — 사용자 승인·준비 중

최신 실행 결과는 [후보32 생성·정적 검사·정확 복구](candidate32-built-20261103.ko.md)입니다. source5178b8e에서 기존 키로 AAB1회를 생성했고 두 ABI native12·서명/기본 검사를 통과했습니다. 아래의 미빌드/서명 대기는 준비 이력이며 Play 업로드·제공·실제 게임 실행은 아직 남습니다.

후보31은 정상 Play 설치를 확인했지만 LD의 사용자 첫 실행은 흰 화면입니다. [실제 제공·설치·진단 결과](internal31-live-20261103.ko.md)를 바탕으로 **ARM64 지원을 유지하면서 x86_64를 함께 담는 다음 내부 후보**의 구현·격리 검증·일회 독립 읽기 검토를 사용자가 승인했습니다. Console 전체23개·최고31·32검색0 확인 뒤 소스 버전32를 준비했습니다. 명시 ABI 프로필·관련 합성 검사·독립 읽기와 새 계획/서명 metadata 준비를 마쳤으며 [구현·검증 기록](candidate32-abi-tools-20261103.ko.md)에 후속 실행과 종료 경계의 보류를 구분했습니다. 새 Android 빌드·키 입력·업로드는 아직 하지 않았습니다.

## 근거와 한계

- 실제31은 Play 설치 출처·기존 UID/데이터 경로/최초 설치 시각 유지, 분할APK4개 Play 서명·원래 native6개/광고 설정 payload 일치를 확인했습니다. 설치 경로 대기는 해소했으며 게임/로그인 성공은 아닙니다.
- 사용자 실행1회에서 Unity/IL2CPP JNI·GLES3.1·Swappy까지 기록됐고 흰 화면과 Loading.AsyncRe/FMOD stream/AudioTrack의 지속 CPU 사용을 관측했습니다. 수집 로그에 fatal/관리 예외는 없으나 완전한 무결함 증거는 아닙니다.
- 같은 LD에서 이전 ARM64 사진 앱과 x86_64 격리 앱은 렌더를 관측했지만 새 ARM64 빈 장면/손님 시험과 실제31은 첫 화면에 도달하지 못했습니다. 이전 x86 검증은 최신 SDK 보고 보완 전이므로 새 운영 성공을 대신하지 않습니다.
- EGL/gspd/Houdini 안내는 정상 대조군에도 있습니다. ARM 변환 경로가 조사 대상이지만 특정 오류·라이선스 날짜·그래픽 API·제품 로직을 원인으로 확정하지 않습니다.

| 후보 구성 | 기존 ARM64 + x86_64·min25/target36·같은 게임/로그인/광고/구매 로직·미사용 새 버전 코드 |

Google의 [installer check 안내](https://support.google.com/googleplay/android-developer/answer/15621622?hl=en)는 x86_64도 보호 지원 ABI로 설명합니다. 현재 보호 설정을 유지한 정상 Play 경로를 사용합니다. 이 지원 사실이 이 게임의 x86_64 실행 성공을 보장하지는 않습니다.

후속 설치에서는 실제 code/installer/UID/서명·전달 CPU를 확인한 뒤 사용자 첫 실행과 기존 계정/저장·No Ads·연령별 광고/SDK·삭제를 검증합니다. x86_64가 성공하더라도 **실물 ARM64 시작과 실제16KB 검증은 계속 별도 잔여**입니다. ARM64를 제거해 검증을 대체하거나 최종 정책 심사/프로덕션을 진행하는 승인은 아닙니다.

이미 설치된31을 지우거나 이전 코드로 강제 되돌리는 복구는 계획하지 않습니다. 새 후보는 정상 Play 업그레이드로 연결하며 새 코드가 등록되면 재사용하지 않습니다. 기존31의 AAB·실제 분할APK·로그와 원본을 보존합니다. [전체 잔여](remaining-recovery-work.ko.md)
