# 사용자 수동 전달과 Console 확인 순서

2026-10-24: 사용자가 Chrome 작업을 직접 맡습니다. 자동 제어 도구의 URL 판별 오류 때문에 멈춘 단계이며, Chrome 재개 승인 부족이나 사용량 제한 때문이 아닙니다. 파일 전달과 운영 출시 준비를 구분합니다.

## 1. Drive와 휴대폰: 지금 가능한 확인

준비된 `Tamer-gameplay-c6b4ba1.apk`·`SHA256SUMS.txt`·`설치와 첫 확인.ko.txt` 세 파일을 기존 Tamer Drive 폴더에 올립니다. 계정/공유 설정을 변경하거나 공개 링크로 전환할 필요는 없습니다. APK의 정확한 크기·해시는 [빌드 기록](gameplay-delivery-20261024.ko.md)을 따릅니다.

1. 휴대폰에서 APK를 내려받아 업데이트 설치합니다. 운영 앱·IAP Test와 별도인 오프라인 시험 앱입니다. 이 파일을 Play Console에 올리지 않습니다.
2. 서명 충돌·설치 오류는 화면을 남기고 알려주세요. 기존 앱 삭제나 데이터/캐시 초기화로 해결하지 않습니다.
3. 실행 후 Main 첫 화면을 캡처합니다. Google 로그인이나 계정·암호 입력, 구매는 필요하지 않습니다.
4. `Repeat Main / Game / Main` 버튼을 한 번 누릅니다. 대략30초 동안 추가 입력 없이 기다린 뒤 `ROUNDTRIP_OK count=1` 화면을 캡처합니다. 실패·정지·앱 종료라면 그 화면을 남깁니다. 같은 조건으로 반복하지 않아도 됩니다.
5. 이 확인에는 Capture 보조·무적·새 구매·실제 계정 연결이 필요하지 않습니다. 앱을 다시 시작하면 새 합성 프로필을 쓰므로 운영 저장 복원 시험으로 해석하지 않습니다.

LD에서는 [같은 파일 왕복](gameplay-roundtrip-20261024.ko.md)을 확인했습니다. 휴대폰의 설치·렌더링·입력 결과는 아직 별도 미검증입니다. 캡처의 화면 카운터는 Android 전체 로그 오류 수와 다릅니다.

## 2. 최종 AAB 준비에 우선 필요한 화면

아래는 **운영 Monster Tamer**에서 확인합니다. IAP Test 앱의 숫자·인증서를 운영 앱에 대신 적용하지 않습니다. 화면 이름은 Console 언어·배치에 따라 다를 수 있으므로 대상 앱과 표제도 함께 확인합니다.

| 필요한 자료 | 볼 화면·남길 내용 | 용도 |
| --- | --- | --- |
| 전체 사용 versionCode | App Bundle 탐색기/전체 버전 목록: 운영 앱 이름과 버전코드·트랙이 보이는 화면 | 모든 트랙의 사용 최대값 확인 후 새 후보 번호 결정. 특정 트랙 하나만 보고 확정하지 않음 |
| 현재 활성 공개 인증서 | 앱 무결성/앱 서명: **업로드 키 인증서**와 **앱 서명 키 인증서**의 구분·SHA-256, 변경 대기 여부 | 빌드 서명용 업로드 인증서와 설치 제공물의 앱 서명을 각각 대조 |

공개 인증서 지문은 개인키·암호가 아닙니다. keystore 파일·암호·개발자 키·OAuth 비밀값은 캡처하거나 채팅에 붙이지 않습니다. 개인 계정/이메일이 함께 보이면 가려도 됩니다. 원본 화면은 비공개 작업 근거로만 취급합니다.

이 두 자료만으로 운영 광고·정책 승인이나 서명 가능성이 자동 확정되지는 않습니다. 키 암호 입력이 실제로 필요해지면 준비된 입력창과 정확한 파일을 별도로 안내합니다. 현재 최종 운영 서명 AAB는 없으므로 지금 AAB 업로드를 요청하지 않습니다.

## 3. 운영 자료 후속 대조

다음에는 Play의 대상 연령·국가/지역·Data safety·개인정보/삭제 URL 상태와 AdMob의 앱·보상형 단위·게시 유럽/미국 메시지·파트너 구성을 대조합니다. 기존 비공개 설정/캡처는 과거 근거이며 현재 Console 확인이나 승인으로 바꾸지 않습니다. 파트너 목록 차이와 지역 검토가 해결되지 않으면 운영 광고 승인은 보류합니다.

9세 이상 성인 포함, 기존 국가, rewarded 완료 후 buff, 영구 No Ads, PlayFab 유지, 기존 문의 메일의2주 처리,5초 닫기 추가 조사 보류는 이미 정한 방향입니다. 같은 제품 결정을 다시 묻지 않습니다. 시험 근거를 정책 심사 통과나 공급자 전체 삭제 완료로 표시하지 않습니다.

실제 운영 자료/허용 범위·소스·서명 입력이 고정되면 최종 AAB를 만들고 검사합니다. 이후 사용자 수동 업로드→같은 제공물의 설치·필요 기능/스토어 확인→시험 자원 정리→최종 문서와 저장소 소문자 변경 순서로 진행합니다.
